---

## 2. Verdict

**NOT M-invariant on real weights — the batched path reproduces the divergence.**

- The core question — *is batched shared_experts numerically M-invariant?* — is answered **NO** on real weights: `qmv_wide(M=4)` vs `qmv(M=1)` diverges on 13/131072 elements (0.0099%), max 2⁻⁹. This is the same divergence class the 2026-08-04 bisect isolated (0.023%), now reproduced offline on real layer-3 weights.
- The proposed "middle ground" (zero-pad to force `qmm`) is **not demonstrated lossless**: on the synthetic weight only M=8 is 0-ulp; M=16/32/64 diverge by 1 ULP. And its real-weight numerics were **not captured** in the JSON.
- Speed-wise the middle ground is marginal: padded-qmm (257 µs) is only ~4% faster than per-row (268.5 µs) on real weights, vs the 32.5% win of the (divergent) batched path. So even if it were lossless, it captures little of the win.

**Bottom line:** Phase C's candidate fix is **structurally weak** — no numerically-lossless batched formulation was demonstrated. The batched path is confirmed divergent on real weights; the padded-qmm fallback is neither proven lossless nor fast enough to be attractive.

---

## 3. What additional data would be needed for a confident conclusion

1. **Real-weight padded-qmm numerics** (the missing B3 numbers): re-run `real_shared_m_invariance.py` and capture the `padded-M vs per-row ref` max-diff into the JSON. This is the single most important gap — it directly answers whether the middle ground is lossless on real weights.
2. **Real-weight qmm at M=8** specifically: the synthetic test showed M=8 is the only 0-ulp padding level; confirm whether M=8 qmm is also 0-ulp on real weights (and whether M=8 padding is fast enough to matter).
3. **Multiple layers / multiple M values on real weights**: only layer-3 gate_proj (w1) was tested. The divergence magnitude is value-dependent; a couple more layers (and up/down projections) would firm up the 0.0099% figure.
4. **A captured run log for the real-weight test** (like `run_shared_kernel_test.log` for the kernel test) to confirm the B3 prints and rule out a partial/interrupted run.

## 4. Notes / caveats

- The two files are small (404 B and 344 B) and each captures a single run. The kernel test is on a **synthetic** weight (script explicitly notes real shared weights were not extracted); the real test is on **one** layer's gate_proj. Neither is a multi-run statistical sample.
- The synthetic kernel test's `qmv_wide`=0.0 result **contradicts** the real test's nonzero divergence — expected, since the script notes divergence magnitude is value-dependent (mechanism is accumulation-order in the kernel, not the specific weights). The real-weight number is the authoritative one.
- The script header's claim that `qmm` is a "0-ulp batch-invariant GEMM family" is **not supported** by the measured data (1 ULP at M≥16 on synthetic).
- No adjacent bugs found in scope; the only issue is the missing B3 numerics in the real-weight JSON (flagged above).
