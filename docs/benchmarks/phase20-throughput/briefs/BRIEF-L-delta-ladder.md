## Mechanics you must get right (all from this repo's hard-won history; cite in LADDER-NOTES.md)
1. **Row truth comes from the engine log**, not from your estimate: `[DSV41] turn reuse: prompt=N prefill=M reuse=R cache=C rewind=W UNCOMMITTED` (emitted when `session.prefill` returns, only if reuse>0).
   `delta_rows = M`. Prefill start marker: `[DSV41] prefill controls: ... (rows=M, base=2048)` (not emitted for every small delta) else `API request: POST`. `prefill_s = t(turn reuse) - t(prefill controls)`; also compute the client-side TTFT-based rate (`M / ttft`) as a cross-check and report both. For fresh (cold) feeds there is no turn-reuse line: rows/s = `usage.prompt_tokens / TTFT` (the prior campaign's method: 100000/373.9 = 267.5).
   Fetch log lines by ssh from the API node and the other node: record `stat -f %z ~/.exo/exo_log/exo.log` (byte size) BEFORE each request and `tail -c +<size+1>` AFTER it (read-only; log rotates only at relaunch). Node log times are node-local CDT without tz marker.
2. **A "delta" only exists if the prompt's LCP reaches a checkpoint.** `SessionCache.plan()` rewinds to the newest checkpoint at or below the LCP; checkpoints exist at turn/prompt ends (+ a 1024-row ladder + a margin rung ~512 rows before a delta end). Appending text to the SAME user message changes the trailing template tokens and collapses to a rung. The real agentic shape (and the one the 42-call turn exhibits) is a multi-turn extension: `messages = [user: base, assistant: <the reply text the server returned for the base>, user: <new text>]`, whose rendered prefix contains the previous prompt exactly.
   Therefore: build the base conversation once per (ctx) as `[{"role":"user","content": SALT + filler(ctx tokens)}]`, `max_tokens=1`, `temperature=0`, stream; capture the reply; each delta rep = the 3-message form above with a NEW salted-free unique delta text of ~D tokens. After each rep the resident conversation has moved on (`base+D1`), but the next rep's LCP with it is the base prompt end (+ reply), so the engine rewinds to the base's prompt-end checkpoint: **reps branch from the same base depth** (depth fixed across reps). VERIFY from the log that `reuse` ~ base size (within a few hundred rows) for each rep; a rep whose `reuse < 0.9 * base_rows` is `collapsed` - exclude from the table but list it with its numbers (the `reuse undershoot` WARNING also flags it).
   Delta size labels are NOMINAL (you tokenize by chars/token); the table must carry the ACTUAL `prefill=M` from the log. Calibrate chars/token from a real `usage.prompt_tokens` (the battery's filler measured 5.111 chars/token, phase19's sentences 5.59 - do not assume; make it `--chars-per-token` with a startup self-calibration option: send a ~2K-token pilot and read `usage.prompt_tokens`).
3. **Unique salt, once, at the head** of every base (`SALT-<secrets.token_hex(8)>`): park/restore persists conversations ACROSS relaunches, so a reused filler can match a restored session (observed fake 1914 tok/s). Never re-salt inside the filler (it re-tokenizes the prompt). Verify every feed that you believe is fresh has NO turn-reuse line (or reuse ~ 0).
